# 独立演练记录

共 15 个场景，由 4 个无主线程历史的只读子代理分组演练，只接收原始输入和当前 Router，不接收 expect。记录为归一化的动作与依据摘要，并非原始执行日志，也不是产品宿主实际运行。

首轮 14/15 通过。apifox_summary 的回复将“响应不变”误述为变化，初始 JSON 保留 reviewIssues，使评分器将此项判为失败。在 Apifox 阶段增加只报告已证实变化、保留明确不变项的规则后，重新派发独立代理，只读取摘要路径；新结果正确说明 GET /orders 新增可选 status=pending/paid，响应不变。其用户摘要还列出文档/Mock/测试同步项，以及未提供的错误码/权限待确认。修正记录将此例替换为新的演练结果，其余 14 例保留首轮结果。

评分复核接受等价动作：缺少必要需求边界时允许先 clarify，而非必须立即 write-spec；恢复记录或场景已给 freshRead 时允许 read-recovery-evidence，不强制重复 read-apifox。未因此放宽任何写入授权或禁止动作。行为依据仍须人工核对，评分器本身不理解自然语言事实。

后续独立规则审查发现：创建超时后的空列表不能排除原请求延迟落地。补充原请求幂等键/权威终态证据条件，并增加第 16 例 apifox_delayed_create。新的独立代理在原始空列表、最终一致性和原请求可能晚到的场景下选择保持 unknown、停止依赖写入、不重试。原始动作标识保留在 originalActions，评分动作作等价归一化。首轮 JSON 保留 15 例，因此在当前 16 例评分器下另有 1 例 unverified。

最终 16/16 是独立决策演练结果。真实 Git 组合/冲突由隔离仓库测试覆盖；Apifox 仅使用原始响应夹具，没有真实项目写入。Codex/Claude/Cursor 的模型执行效果不能由这份记录推出。
